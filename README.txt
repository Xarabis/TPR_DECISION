DECISION / 01 — игра «Подземелье» для зала (пилот 5: лифт, облако, лимиты, защита голосов)

ЗАПУСК
1. Установи Node.js (https://nodejs.org), если его нет. Больше ничего ставить не нужно.
2. Дважды щёлкни start.bat. Откроется экран ведущего. Windows может спросить про сеть:
   разреши доступ для частных сетей.
3. Телефоны должны быть в той же Wi-Fi сети, что и ноутбук. QR на экране ведёт на адрес ноутбука.

ЕСЛИ ТЕЛЕФОНЫ НЕ ВИДЯТ НОУТБУК (в вузах Wi-Fi часто изолирует устройства друг от друга)
QR из start.bat ведёт на локальный адрес ноутбука (192.168.x.x): из чужой сети он не откроется.
Есть три рабочих пути, от лучшего к запасному.

ПУТЬ 1 (рекомендую). Сервер в интернете, Railway. Ссылка постоянная, работает с мобильного интернета.
  Нужен аккаунт на railway.com и Node.js на ноутбуке. Два способа, выбери один.

  1А. Через CLI, без git (быстрее всего для проверки):
    npm install -g @railway/cli
    railway login
    railway up                       (создаст проект и сервис, загрузит папку, запустит npm start)
    railway variable set HOST_KEY=ДЛИННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ     (старая запись railway variables --set тоже работает)
    railway domain                   (выдаст публичный адрес https://....up.railway.app)
  Если railway up спросит про проект, создай новый и назови decision01. Команды сверяй с docs.railway.com.

  1Б. Через GitHub (удобно, если будешь дорабатывать):
    1) На github.com создай ПРИВАТНЫЙ репозиторий decision01 без README.
    2) В папке с server.js:  git init, git add ., git commit -m "pilot 5", git branch -M main,
       git remote add origin https://github.com/ЛОГИН/decision01.git, git push -u origin main
       (.gitignore уже есть; ключ HOST_KEY в репозиторий НЕ кладём, он живёт только в Railway.)
    3) Railway: New Project, Deploy from GitHub repo, выбери decision01, ветку main.
    4) В сервисе: Variables, добавь HOST_KEY. Settings, Networking, Generate Domain.
    Каждый git push будет сам перевыкладывать приложение. Во время игры push не делай.

  Настройки сервиса (railway.json в папке уже задаёт запуск npm start и проверку /healthz):
    реплик ровно 1 (состояние игры в памяти одного процесса), App Sleeping / Serverless выключен,
    HOST_KEY задан, PORT не трогать (его выдаёт Railway).

  Экран ведущего открывай ТАК:  https://ТВОЙ-АДРЕС/host?k=ТВОЙ_КЛЮЧ
  QR на экране сам поведёт на этот же адрес. Телефоны заходят по QR или на https://ТВОЙ-АДРЕС/play
  Проверка: /healthz отвечает ok; открой адрес с телефона на мобильном интернете (Wi-Fi выключи).
  Деплой делай за день до выступления. Любой перезапуск или новый деплой обнуляет игру.
  После выступления останови сервис, чтобы не тратились кредиты.

  Защита: у каждого игрока секретный токен (32 символа), он нигде не показывается другим;
  по публичным данным с экрана ведущего за чужого игрока проголосовать нельзя.

ПУТЬ 2. Хот-спот ноутбука. Включи «Мобильный хот-спот» в Windows, студенты подключаются к нему
  Wi-Fi-ом, QR из start.bat работает как есть. Интернет им не нужен. Минус: сеть, не интернет,
  и ноутбук раздаёт её в пределах комнаты.

ПУТЬ 3. Другой облачный хост (Render и подобные): тот же package.json, команда запуска npm start,
  переменная HOST_KEY. Бесплатный Render засыпает через 15 минут простоя и просыпается около минуты:
  для зала не годится, если не "разбудить" его заранее.
  Не используй cloudflared quick tunnel (trycloudflare): он не поддерживает SSE, а игра на SSE.

ЛИМИТЫ. Весь зал может сидеть за одним адресом (общий Wi-Fi вуза). Поэтому лимит 400 запросов в секунду на адрес
и 8 в секунду на одного игрока. Если сервер всё же ответит «занято», телефон сам повторит выбор до 5 раз и скажет об этом.

УПРАВЛЕНИЕ (экран ведущего)
Пробел, → или клик по подсказке внизу — следующий шаг:
  лобби → начать игру → закрыть голосование → бросить кубик → следующий этаж → итоги
Р — игра заново (имена остаются, баланс обнуляется). U — переключить адрес QR, если у ноутбука
несколько сетей. F — полный экран.

ПРАВИЛА ИГРЫ
Этажи: 1 — в руках 100, шанс пройти 80 %, дальше 150; 2 — шанс 60 %, дальше 300; 3 — шанс 20 %, сундук 1200.
Каждый этаж игрок выбирает «забрать» (выходит с этим золотом) или «идти дальше».
Не успел проголосовать — считается «забрать». Кубик 0–99 бросает сервер, проход если выпало меньше шанса.
Кто зашёл после старта, наблюдает. Имена и баланс хранятся только в памяти сервера: закрыл окно — всё исчезло.
В конце топ-10 на большом экране, а у каждого игрока на телефоне свой баланс на весь экран.

ЛИФТ (подлянка, только на этаже 2)
На втором этаже появляется третья кнопка «Лифт»: на ней написано только «золото не сгорит», цифр нет.
Вверх (шанс 70 %): игрок пропускает этаж 2 без кубика, золото при нём, идёт на этаж 3 с тем, что было в руках (150).
Вниз (30 %): игрока отбрасывает на этаж 1, он снова проходит на этаж 2 кубиком 80 %. Не прошёл — ловушка, 0.
Прошёл — сундук на этаже 2 пуст, лифт не работает. Итог внизу всегда 0, второй кубик только для драмы.
По расчёту: лифт в среднем 0,7 × 240 = 168 (240 = 0,2 × 1200 за сундуком), лестница 0,6 × 300 = 180, «забрать» 150.
Шанс вверх меняется одной строкой в server.js: LIFT_UP = 70. На итоговом экране показывается, сколько человек выбрали лифт.
